# LearnZì — project hand-over note

Attach this note and `learnzi-source.zip` (or point to the GitHub repository) in a new Claude chat, then say what to do next. The live app is the private artifact "LearnZì" (claude.ai/artifact/586ZXu8TrHvv42JDQycXwq). Always update it by publishing to that URL so the link and the synced data stay the same.

## Working rules
- The user has no programming knowledge. They give instructions in plain English; Claude builds, tests and publishes.
- **Never print raw dictionary data (CC-CEDICT lines, word lists, sentence lists) into the chat.** Earlier chats were blocked by content filtering, most likely because raw dictionary entries (which include crude slang) appeared in the chat. Only print counts and file sizes when checking data.
- Build in small, separate source files joined by the build script. One change at a time; test headlessly on a phone size (400×860) and a desktop size (1280×900) before publishing.
- The user usually wants to discuss a list of changes before building ("Let's discuss before making changes"). Small, clear requests can be built straight away.
- Back up to GitHub (see Backups). Never ask for a password: GitHub access goes through Claude's settings.
- End each piece of work with a short plain-English summary of what changed and what to test.
- Security habits: all imported and user text is shown as text only (textContent, never innerHTML); no trackers, analytics or secret keys; files opened from the device are never uploaded; libraries pinned to exact versions.

## The app
LearnZì is an open-source Chinese word-learning app for an absolute beginner, used by one person on an Android phone (the Claude app and Chrome) and a browser-only PC (Chrome; nothing can be installed). The Claude app's page viewer can't open files or speak; Photo to words and Watch need Chrome.

## Hosting, sync and backups
- **Hosting:** a private Claude artifact (one HTML page plus supporting files). Capabilities `db` and `user` (carried forward on every publish; don't pass `capabilities`).
- **Published files (121):** `dict.txt`, `chars.json`, `sentences.txt`, `daily.txt`, `strokes/s00–s47.json`, `audio/index.txt`, `audio/w00–w47.mp3`, `audio/s00–s07.mp3`, `ocr/` (ort.wasm.min.js, ort-wasm-simd-threaded.mjs, ort-wasm-simd-threaded.wasm, keys.txt, det.ort.txt, rec.onnx.txt), `samples/` (sample-video.mp4, sample-subs.txt, sample-photo.jpg, sample-audio.mp3, sample-audio-text.txt). A publish without `files` keeps them all; only pass `files` for new or changed ones. Served types only (e.g. .tsv → .txt, binary models → base64 .txt).
- **Sync:** three private documents per user: `data/users/<id>/progress` (flashcards and daily activity; merged card by card, latest review wins, daily counts take the max of each slot), `data/users/<id>/state` (settings, decks, folds, etc.; newest `updatedAt` wins) and `data/users/<id>/reader` (Reader text up to 75,000 characters). Everything read from storage or sync is validated (`sanitize`, `sanitizeProgress` in 00-core). Without sync it falls back to browser storage and the pill says "On this device". `data/users/<id>` is private even from the owner, so Claude can't read the user's progress.
- **Backups:** (1) the artifact itself lives in the user's artifact gallery, separate from any chat, and holds every built data file (read them back with Artifact read + `path`); (2) `learnzi-source.zip` (src, tools, this note) is sent after every change; (3) GitHub: public repository **AlphonseV7/Learnzi** (attach with add_repo, access "push"; contains src/, tools/, this note, README, LICENSE, ATTRIBUTION, SECURITY; no built data or test media). If a push is refused, the user must give the Claude GitHub app access to that repository (GitHub → Settings → Applications → Claude → Configure → Repository access).

## Features (how they work)
**Look up and dictionary.** Search by characters (simplified or traditional), pinyin with or without tones, or English (ranked: main meaning > HSK > single-meaning words > frequency; names after everyday readings). Every result is its own box; groups fold and move. Random button; "Word by word" for short English phrases; recent lookups; camera button opens Photo to words. Simplified/traditional switch, pinyin above characters, tone colours (theme, classic, colour-blind friendly or custom).

**Word pop-up** (bottom sheet on phones, slide-in panel on desktop; pull down to close on phones). Boxes that fold, move and can be removed: pronunciation tips (3rd-tone pairs, 不/一 changes, neutral tone, Listen slowly), meanings, stroke order (Hanzi Writer 3.7.3 from jsDelivr with integrity hash: Play, Step, Loop, Trace, From memory +3 XP), character stories (Make Me a Hanzi), words with a character, how common (frequency + HSK), Tatoeba examples, my notes (synced), From your video (see Watch). Star (My Zì), + Deck picker, Settings → Word details switches.

**Reader.** Paste or import .txt/.md/.srt/.lrc/.csv (UTF-8, UTF-16, GBK/GB18030, Big5), pages of ~1,500 characters, tap words, Listen, pinyin toggle. Synced (75,000 characters).

**Audio.** Every recording is tidied as it loads (`16b-dsp.js`): silence trimmed against its own noise floor while keeping the voice's natural fade (the old trim chopped endings), 5 ms fade in, 40 ms fade out, levelled to −16 dB with a 0.95 peak limit (loudness spread across recordings 11.6 dB → 3.6 dB). Stopping fades out over 30 ms. Listen slowly is 25% slower with the same pitch (WSOLA time-stretch; the old version lowered the pitch by 20%). No speed setting: recordings play at native speed. `speak(text, p, {slow, source})` tries: whole-word recording (audio-cmn HSK words and characters by Yue Tan; `wordRecKey`: any word of 2+ characters that has one, single characters only when the dictionary has one reading for them, e.g. 我 yes, 行 no; 你好 and 中国 have no recording in audio-cmn, so they offer two voices) → word built from syllables (Chen Wang; tone changes applied) → browser voice (long sentences go to the browser first when the device has a Chinese voice). `state.voiceSrc` (Automatic · Recording · Syllables · Browser; Settings → Voice) puts your pick first. No floating now-playing bar any more: every Listen button has a voice button beside it (`voiceBtn` / `withVoice` in 16-audio): a speaker whose waves show the voice (smooth arcs = recording, dots = syllables, zigzag = browser), label on full-size buttons, icon only beside icon buttons. It shows the voice that will speak that text (your pick if it can, else the next); tap it to flick to the next available voice, hear it, and remember it (other voice buttons on the page update). Places: word pop-up, pronunciation tip (slow), example sentences, word of the day, sentence of the day, Home greeting, Word by word, flashcards (Listening cards and Listen buttons), Reader page, Photo to words, Settings test, tone trainer (which keeps its own choice in `state.toneSource`). The speaker credits are in each button's label and in Settings → Sources.

**Flashcards, decks, XP.** FSRS-4.5 with learning steps 1 and 10 min; study days start 04:00. Card types per word: Meaning, Listening (memory ≥ 3 days), Recall (≥ 8 days), Writing (optional, ≥ 12 days). One memory per word across decks. Decks: Starred, Welcome (58 first words), HSK 1–6, your own (up to 50, 6,000 words in all, synced in `state.decks`). XP per grade 2/6/10/12; lookups and new words +2/+5 (50 a day); tone trainer 2 per correct (40 a day); watching 1 per line (30 a day). Levels: 100 XP for level 2, +50 more per level (level 100 = 252,450 XP; a simulated steady learner at 10 new words a day earns about 270,000 XP a year, so level 100 is roughly a year). Ranks (`RANKS` in 25-progress), the imperial exam ladder: 学童 Pupil L1, 童生 Candidate L5, 秀才 County graduate L10, 举人 Provincial graduate L20, 贡士 Capital graduate L30, 进士 Palace graduate L45, 探花 Third in the empire L60, 榜眼 Second L80, 状元 First L100; shown under every level bar (tap opens the word; the next rank's name stays hidden: "8 levels to the next rank") and as a ladder on Customise (ranks not reached are ?? / ??? with their level, unless Debug → Show locked items). Level-up screen with theme effect, your avatar (surprised), any new rank and the unlock list. XP from Watch and Listen also triggers the level-up screen (no +XP pop or happy face for those). Stats page (calendar, reviews, due forecast, word strength).

**Home and My Zì.** Home: Greeting (time of day, nickname), Clock (faces Digital, Analogue, 汉字 L3, Pixel L4, Flip L6, Neon L8; effects Glow L2, Heartbeat L5, Comet L7, Rainbow L9, Sparkles 3-day streak; show time/date/both, stacked or side by side; fixed box id `home-clock`), Today's flashcards, Word of the day, Sentence of the day, decks. My Zì (labels say "my" in this tab only: My decks, My cards, My progress, My profile; Home still says "Your decks"): avatar box with Edit, today's numbers, My cards box, My decks, My progress. My cards page (`32b-mycards.js`, view `mycards`): saved (starred) words only, each with a badge per card it has (M Meaning, L Listening, R Recall, W Writing; blue new, orange learning, filled due, green known; tooltip says when it's due), filters by deck (only the saved words in that deck: Welcome, your decks, HSK level by tag) and by status (Due, New, Learning, Familiar, Known), search by characters, pinyin with or without tones, or English, 100 at a time. Customise (tap your avatar): the big avatar, name, level and rank box sits at the top of every tab, then the Avatar | Clock switch.

**Layout and boxes.** Tabs Home · Study · Tools · My Zì (Study: Study now, Decks, My cards, Look up; Tools: Reader, Watch, Listen, Photo to words, Tone trainer; add tools in `NAV_MENUS`). Top bar box with avatar and name, level pill, a compact XP bar between the level pill and the sync dot (52–120 px wide; no search button: Look up is Study → Look up) (`30b-topbar.js`: `xpBarShow` follows `updateTopbar`, MLE level when MLE is on; earning XP sends 2–6 tiny characters from the level pill into the bar, taken from the word studied, looked up, starred or heard in the tone trainer, else 经验值; dot shimmer while filling; a level up fills it, glows, then starts again; no characters with reduced motion). On phones and tablets (not the desktop layout) the top bar is sticky, tucks away after 2.8 s without scrolling, comes back on any scroll, XP, Again or level up; sticky boxes below it (Look up search row, Watch subtitles column, tone garden) move down by `--bar-off` while it shows. Every page has a header box (`PAGES` in 07-page) with Fold all / Open all and "Bring back N" for removed boxes. Boxes fold (`state.folds`; on every page except Home and Look up results they start folded until you open them, `OPEN_VIEWS` in 06-fold; the word pop-up keeps its own defaults), move by dragging the ⠿ grip (on touch, hold it still for 0.4 s first; a swipe from the grip scrolls) with a ghost copy and a dashed landing slot, or arrow keys (`state.order`), and can be removed with × and Undo (`state.hidden`; not Settings, Debug or search results). Settings → Reset → Box layout resets (Original order, Show removed boxes, Open all boxes, Reset all boxes). Desktop (`desk`: ≥ 760px with a mouse): full-width top bar, menu and word panel slide in from the edges.

**Look.** Customise → Theme tab (`34b-theme.js`): themes, light or dark, accent or custom colours, background scene, theme shapes, avatar matches theme. Settings → Text and layout keeps the Chinese and English fonts, text size and box layout (setting rows are shared helpers `setRow`, `setToggle`, `setSeg`, `setSelect`). Themes: Ink, Jade, Porcelain, Lantern, Night Market, Retro Arcade, Cyberedge (free), Peach Blossom (level 4), Imperial (level 8), Custom (four colours with readability warning, shapes from another theme). Each has its own fonts, box shapes, background scene and level-up effect (switches in Customise → Theme: Theme shapes, Background scene, Avatar matches theme). Light or dark: Theme's own · Light · Dark · Match device (`state.mode`; every theme has both looks, colours in 09-modes.css; all text contrast checked). Accent colour, Chinese font, English font, text size. Avatars: five starters (Panda, Lucky cat, Tiger, Jade rabbit, Dragon): the one picked in the welcome (`state.avatar.starter`, default panda) is level 1 and the other four follow at 2–5 in that order (`starterLevel`, a getter on `lv`); then Red panda L8, Koi L12, Crane L16, Golden monkey L20, Nine-tailed fox L30, Qilin L40, Phoenix L50, then the Four Symbols 四象: White Tiger 白虎 L60, Black Tortoise 玄武 L70 (with its snake), Vermilion Bird 朱雀 L80, Azure Dragon 青龙 L90, and the Golden Dragon 金龙 L100 (birds draw a beak instead of a mouth); eyes, accessories, auras; extras Sparkles (3-day streak) and Halo (L15); blush always on. Faces aren't chosen, they react (`setMood` in 27-avatars): calm; happy for 2 s after earning XP; surprised on a level up (beats other moods for 6 s); sleepy after 2 minutes with no tap, key or scroll (not while a video or recording plays), waking on any input; a wink when you tap your avatar; oops (sweat drop, worried brows) after Again. Only avatars made with `liveAvatar()` plus the top bar react; Customise tiles stay calm. Settings → Look → Avatar matches theme (`state.avMatch`, on by default): ink sketch on Ink, pixels on Arcade, neon on Cyber, otherwise the standard look. Next: give every theme its own avatar look.

**Tone trainer.** Start page: Single tones and Tone pairs buttons look the same until pressed; the water garden shows only during a round. Single tones and tone pairs, real recordings, voice button (its own remembered voice), hear every option after answering. Water garden (21 stages, natural colours, grows with correct tones, never shrinks; `progress.garden`).

**Photo to words** (Tools, or the camera button on Look up). Take/choose/paste/drop a picture or try the sample; drag a box round the text; Rotate; Read text. Reads on the device with PP-OCRv5 mobile (PaddleOCR, Apache-2.0) in ONNX Runtime Web 1.23.2 (single-threaded, no workers): detection at ≤ 1280 px, recognition per box at height 48, greedy CTC; vertical columns, sideways and upside-down photos handled automatically. ~31 MB on first use, then cached (Cache Storage `learnzi-ocr-1`). Result: tappable text with unsure characters dotted, Fix text, Listen, Open in Reader, Stop for big pages (tip to box one article when over 60 lines), then Make flashcards (shared tick list: new deck or add to one). Test accuracy: clean, small, serif, noisy photo, subtitle and vertical text 100%; traditional 95%.

**Watch** (Tools). Choose a video (MP4, MKV, WebM, MOV; checked by its first bytes before playing) and its subtitles (.srt, .vtt, .lrc), or try the sample. Desktop ≥ 1000px: video left, subtitles and all lines right (sticky); phones stack. Subtitles box with sizes S/M/L/XL (`state.subSize`), Hide (tap to peek) and early/late ±0.5 s. Tap a word: video pauses and the word opens. Previous / Replay / Next (← → R, Space), speed 0.5–1×, Pause after each line, Loop line, Full screen with tappable overlay, Read the picture (frame → Photo to words). Remembers your place per video on this device (localStorage `learnzi.watch.v1`). Make flashcards from the subtitles: each word keeps the line and time it's first said (deck `videos: [{name, size}]`, word `v: [start, end, video index]`, `x` = the line); flashcards and the word pop-up then show "From your video" with Play the clip (plays just that moment if the video is open on this device, otherwise asks for the file again). **Listen** (the Audio tab on the Watch page; Tools → Listen opens it, Tools → Watch opens the Video tab; header becomes Listen 听书). The same player code runs both tabs: `players.video` and `players.audio`, with `watch` pointing at the tab on screen (`setWatchTab`; switching pauses the other). Same controls as Watch, worded for sentences ("Now reading", "All sentences", Hide the text). Each sentence heard earns 1 XP from the same 30-a-day allowance as Watch. ## Security notes
- Files opened from the device (photos, videos, subtitles, text) stay on the device; nothing is uploaded or stored on a server. Subtitles and imported text are parsed as plain text and shown as text only. Videos are checked by their first bytes and played by the browser's own sandboxed player. Re-encoding ("stripping") videos was considered and isn't needed while nothing is shared with other people; it would be if sharing were ever added.
- Outside code: Hanzi Writer from jsDelivr with an integrity hash; ONNX Runtime Web and the reader models served with the app; Google Fonts for typefaces.

## Known limits and ideas for later
- **Sync document size (important).** The sync store holds at most 256 KB per document. Flashcard progress is one document and grows about 1.9 KB per day at the default 10 new words a day (simulated: 158 KB at 3 months, 322 KB at 6 months, 680 KB at a year), so progress sync would stop at about month 4–5 (it keeps working on the device; other devices stop updating). Fix proposed, not built yet: split progress into several documents (cards by a hash of the word, plus one for daily activity), merged the same way. The state document (saved words, decks) is far from the limit in normal use.
- Published files: 121 files, 119 MB of the 256 MB a version may hold (audio 43.6, stroke data 29.5, photo reader 29.4, dictionary and page 14.7, samples 1.7); largest single file 12.3 MB (limit 16 MB text, 15 MB binary). The page itself is 0.6 MB of 16 MB. A phone downloads only what it uses.
- Factory reset (Settings → Reset, `51-reset.js`): warning dialog, then a glitch, a brush wipe and 清; writes fresh state, progress (new reset epoch) and reader, waits up to 4 s for sync, clears other learnzi.* keys, session storage and learnzi caches, then restarts in place on Home.
- Word splitting has no model for unknown names (小明 splits as 小 + 明).
- The dictionary takes ~1 s to prepare on a PC, 2–3 s on a phone (a Web Worker could help).
- Kai, Brush and Playful fonts are mostly simplified-only.
- Still to confirm on the user's devices: the photo reader on claude.ai's hosting (WebAssembly), and MKV playback in Chrome.
- Decided against or skipped: Chinese interface, e-book import, an "Ask Claude" button (open-source data only). Possible later: Export to Anki.
